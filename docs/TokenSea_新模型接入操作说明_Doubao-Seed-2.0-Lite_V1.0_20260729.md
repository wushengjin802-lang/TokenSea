# TokenSea 新模型接入操作说明

- **示例模型**：Doubao-Seed-2.0-Lite
- **火山方舟在线推理模型 ID**：`doubao-seed-2-0-lite-260215`
- **版本**：V1.0
- **日期**：2026-07-29
- **适用对象**：平台管理员、模型资产管理员、成本管理员

> 本文只说明供应商、模型和价格接入的最短完整流程。业务系统最终只使用 TokenSea Virtual Key 和企业服务模型名，不直接使用火山方舟 API Key 或真实模型 ID。

---

## 1. 总体流程

```text
创建供应商渠道
→ 托管供应商 Key
→ 连接测试并启用渠道
→ 发现模型
→ 能力探测与部署审核
→ 接入官方价格源
→ 提取并审核价格
→ 生成模型生效价格
→ 创建企业服务模型与路由
→ 授权租户并生成 Virtual Key
→ 调用验证
```

---

## 2. 创建火山方舟供应商渠道

进入：

```text
模型配置 → 供应商渠道 → 新建
```

建议填写：

| 字段 | 示例值 |
|---|---|
| 供应商模板 | 火山方舟 / 豆包 |
| 渠道名称 | 火山方舟生产渠道 |
| 协议 | OpenAI-compatible（模板自动带出） |
| API 地址 | `https://ark.cn-beijing.volces.com/api/v3` |
| 区域 | 中国 |
| 环境 | 生产 |
| 状态 | 先保持暂停 |

随后托管密钥：

```text
供应商渠道 → 托管或轮换密钥
```

密钥用途选择：

```text
INFERENCE
```

完成后执行：

```text
连接测试 → 成功后启用渠道
```

检查项：

- API Key 有效；
- `ark.cn-beijing.volces.com` 已加入出口白名单；
- 最小 Chat/Responses 请求成功；
- 渠道状态为“启用”，健康状态为“健康”。

---

## 3. 发现并审核模型

进入：

```text
模型配置 → 供应商渠道 → 火山方舟生产渠道 → 发现模型
```

确认发现结果中存在：

```text
doubao-seed-2-0-lite-260215
```

如果 `/models` 没有返回该模型，不要猜测模型 ID。应以火山方舟控制台实际开通结果和官方 API 示例为准，再通过官方价格源或人工确认生成模型候选。

随后进入：

```text
模型配置 → 模型部署
```

完成：

1. 执行真实能力探测；
2. 确认 Chat/Responses、流式、多模态等能力；
3. 审核模型部署；
4. 参考价格由系统自动同步；暂无参考价不阻止进入生产审核。

---

## 4. 查看自动参考价格

进入：

```text
模型配置 → 参考价格状态
```

系统会在平台启动后自动导入离线参考价，并每天同步 LiteLLM、models.dev 等公共参考来源。管理员无需为豆包模型新建价格源、测试获取、测试解析或逐条审核价格。

检查项：

- `volcengine_ark / doubao-seed-2-0-lite-260215` 是否存在精确参考价；
- 参考价来源、币种、输入单价、输出单价和更新时间；
- LiteLLM 与 models.dev 自动同步任务是否成功；
- 页面明确显示“参考价格不作为实际结算依据”。

当前内置离线参考包包含以下示例：

```text
供应商类型：volcengine_ark
模型：doubao-seed-2-0-lite-260215
区域：中国
币种：CNY
输入参考价：¥0.60 / 百万 Token
输出参考价：¥3.60 / 百万 Token
```

其他 Doubao Seed 2.0 型号如果尚无与 `volcengine_ark + 实际模型名 + 区域` 精确匹配的记录，模型部署页显示“暂无参考价”。这只表示公共参考库暂未覆盖，不影响能力探测、生产审核、路由和调用。

---

## 5. 创建企业服务模型和路由

进入：

```text
模型配置 → 企业服务模型 → 新建
```

示例：

| 字段 | 示例值 |
|---|---|
| 企业服务模型名 | `chat-lite` |
| 展示名称 | 通用对话轻量版 |
| 实际模型部署 | `doubao-seed-2-0-lite-260215` |
| 状态 | 草稿 |

再进入：

```text
模型配置 → 路由策略
```

将 `chat-lite` 路由到火山方舟生产渠道对应模型部署。确认：

- 渠道健康；
- 模型探测通过；
- 参考价格状态已检查；暂无参考价不阻止发布；
- 路由策略已激活。

最后发布企业服务模型。

---

## 6. 租户授权和 Virtual Key

依次完成：

```text
组织与权限 → 租户管理：授权 chat-lite
组织与权限 → 项目管理：创建项目
组织与权限 → 应用管理：创建应用
日常运营 → API Key：创建并批准 Key
```

API Key 的模型范围必须包含：

```text
chat-lite
```

业务系统只使用生成一次的 TokenSea Virtual Key。

---

## 7. 调用验证

```bash
curl http://<TOKENSEA_GATEWAY>/v1/chat/completions \
  -H "Authorization: Bearer <TOKENSEA_VIRTUAL_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "chat-lite",
    "messages": [
      {"role": "user", "content": "请用一句话介绍 TokenSea"}
    ]
  }'
```

验证结果：

- Gateway 返回成功；
- 实际路由到 `doubao-seed-2-0-lite-260215`；
- 调用日志有请求 ID；
- 用量记录包含输入、输出和总 Token；
- 有参考价时成本估算使用当前参考价；暂无参考价时调用仍成功并明确标记为未估算；
- 供应商 Key 未出现在前端、日志或响应中。

---

## 9. 关键原则

```text
发现模型 ≠ 可投入生产
探测通过 ≠ 价格已完整
官方公开价 ≠ 企业合同实际成本
供应商真实模型名 ≠ 业务侧服务模型名
供应商 API Key ≠ TokenSea Virtual Key
```

正式生产使用必须同时满足：渠道健康、能力探测通过、正式价格生效、部署审核通过、路由激活和租户授权。
