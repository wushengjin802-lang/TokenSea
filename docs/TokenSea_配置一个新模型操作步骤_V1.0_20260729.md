# TokenSea 配置一个新模型操作步骤

- **版本**：V1.0
- **日期**：2026-07-29
- **适用对象**：平台管理员、模型管理员、租户管理员
- **适用范围**：在 TokenSea 中接入一个新的供应商模型，并最终通过企业服务模型和 Virtual Key 对外提供调用

> 本文按当前 TokenSea 实际流程编写。公共价格由平台自动同步，仅用于参考估算，不需要为每个新模型手工配置价格源，也不作为供应商结算或租户收费依据。

---

## 1. 总体流程

```text
确认供应商与模型信息
→ 创建或复用供应商渠道
→ 托管供应商推理 Key
→ 连接测试并启用渠道
→ 发现模型或创建模型候选
→ 创建模型部署并完成能力探测
→ 查看自动参考价格
→ 创建企业服务模型
→ 配置路由策略
→ 授权租户、项目和应用
→ 创建 Virtual Key
→ 调用验证
```

---

## 2. 准备信息

接入前至少确认以下内容：

| 信息 | 说明 |
|---|---|
| 供应商 | 例如 OpenAI、DeepSeek、火山方舟、Kimi、OpenRouter |
| API 地址 | 供应商实际调用地址 |
| 协议 | OpenAI-compatible、Anthropic、Gemini 等 |
| API Key | 用于模型推理，密钥用途为 `INFERENCE` |
| 真实模型 ID | 必须使用供应商实际支持的模型名 |
| 模型能力 | Chat、Responses、Embedding、图片、音频、工具调用等 |
| 区域和环境 | 中国、全球；生产、测试等 |

不要根据宣传名称猜测模型 ID。应以供应商控制台、模型列表接口或实际调用结果为准。

---

## 3. 创建供应商渠道

进入：

```text
模型配置 → 供应商渠道 → 新建
```

填写：

| 字段 | 操作要求 |
|---|---|
| 供应商模板 | 优先选择系统内置模板 |
| 渠道名称 | 建议包含供应商、区域和环境 |
| 协议 | 通常由供应商模板自动带出 |
| API 地址 | 模板自动带出后可按实际区域修改 |
| 区域 | 选择实际服务区域 |
| 环境 | 测试或生产 |
| 状态 | 建议先保持暂停 |

如果系统没有对应模板，可选择自定义 OpenAI-compatible 供应商，并手工填写协议和 API 地址。

---

## 4. 托管供应商 Key

在供应商渠道中执行：

```text
托管密钥 / 轮换密钥
```

密钥用途选择：

```text
INFERENCE
```

说明：

- `INFERENCE`：模型调用 Key；
- `PRICING_READ`：价格目录只读凭据；
- `BILLING_READ`：供应商账单只读凭据。

新模型正常调用只需要配置 `INFERENCE`，不要使用价格或账单凭据代替推理 Key。

---

## 5. 测试并启用渠道

执行：

```text
供应商渠道 → 连接测试
```

至少确认：

- API 地址可访问；
- API Key 有效；
- 出口白名单允许目标域名；
- 最小请求能够成功；
- 返回内容符合所选协议。

连接测试成功后启用渠道，并在：

```text
日常运营 → 渠道健康
```

确认渠道状态为健康。

---

## 6. 发现模型或创建模型候选

优先执行供应商渠道的模型发现：

```text
模型配置 → 供应商渠道 → 发现模型
```

然后进入：

```text
模型配置 → 模型候选
```

确认目标模型存在，并核对：

- 真实模型 ID；
- 供应商类型；
- 支持的接口；
- 上下文长度；
- 是否支持流式；
- 是否支持工具调用、多模态或推理能力。

如果供应商不提供模型列表接口，可手工创建模型候选，但必须保存官方依据或实际调用证据。

如系统提示模型别名冲突，进入：

```text
模型配置 → 模型别名审核
```

确认不同来源的模型是否应归并，避免将 OpenRouter 模型与直连供应商模型错误合并。

---

## 7. 创建模型部署

进入：

```text
模型配置 → 模型部署 → 新建
```

建议填写：

| 字段 | 说明 |
|---|---|
| 模型候选 | 选择上一步确认的模型 |
| 供应商渠道 | 选择已经启用且健康的渠道 |
| 实际模型名 | 使用供应商真实模型 ID |
| 区域 | 与渠道一致 |
| 能力标签 | 根据实际探测结果填写 |
| 状态 | 先保持草稿或暂停 |

创建后执行能力探测，确认：

- 非流式调用；
- 流式调用；
- Token usage 返回；
- 工具调用；
- 图片、音频或其他声明能力；
- 超时、限流和错误响应行为。

能力探测通过后审核并启用模型部署。

---

## 8. 查看自动参考价格

进入：

```text
模型配置 → 参考价格状态
```

平台会自动从 LiteLLM、models.dev 和离线参考包同步价格，并每天更新。

检查：

- 模型是否已匹配参考价；
- 价格来源；
- 币种；
- 输入和输出参考单价；
- 最近更新时间；
- 是否已过期。

注意：

```text
参考价格缺失或同步失败
≠ 模型不可用
```

参考价格只影响成本估算展示，不阻止模型部署、路由和调用。无需为每个新模型新建价格源、测试解析或逐条审核价格。

---

## 9. 创建企业服务模型

进入：

```text
模型配置 → 企业服务模型 → 新建
```

企业服务模型是业务系统实际使用的稳定名称，建议不要直接暴露供应商真实模型 ID。

示例：

| 字段 | 示例 |
|---|---|
| 企业服务模型名 | `chat-lite` |
| 展示名称 | 通用对话轻量版 |
| 模型类型 | Chat |
| 状态 | 草稿 |

命名建议：

```text
chat-lite
chat-standard
chat-pro
reasoning-pro
code-pro
embedding-standard
```

这样以后可以替换底层供应商或模型，而不要求业务系统修改模型名。

---

## 10. 配置路由策略

进入：

```text
模型配置 → 路由策略 → 新建
```

将企业服务模型关联到目标模型部署。

配置内容通常包括：

- 主路由模型部署；
- 备用模型部署；
- 权重或优先级；
- 超时；
- 重试；
- 熔断；
- 限流；
- 区域或租户条件。

最小配置可以只设置一个主路由。确认渠道和模型部署健康后启用路由策略，再发布企业服务模型。

---

## 11. 授权租户、项目和应用

依次进入：

```text
组织与权限 → 租户管理
组织与权限 → 项目管理
组织与权限 → 应用管理
```

完成：

1. 租户授权使用企业服务模型；
2. 创建或选择项目；
3. 创建或选择应用；
4. 确认项目和应用均处于启用状态。

---

## 12. 创建 Virtual Key

进入：

```text
日常运营 → API Key → 新建
```

填写：

- 所属租户；
- 所属项目；
- 所属应用；
- 可用企业服务模型；
- 有效期；
- 限流；
- 预算；
- IP 或其他访问限制。

创建并批准后，系统只展示一次完整 Virtual Key，应立即安全保存。

业务系统只使用：

```text
TokenSea Gateway 地址
+ TokenSea Virtual Key
+ 企业服务模型名
```

不直接使用供应商 API Key 和真实模型 ID。

---

## 13. 调用验证

请求地址：

```text
http://localhost:39212/v1/chat/completions
```

示例：

```bash
curl http://localhost:39212/v1/chat/completions \
  -H "Authorization: Bearer ts_你的VirtualKey" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "chat-lite",
    "messages": [
      {"role": "user", "content": "请回复 TokenSea 模型接入成功"}
    ]
  }'
```

验证内容：

- HTTP 状态为 200；
- 返回模型内容正常；
- 调用日志出现记录；
- 用量分析出现输入、输出和总 Token；
- 路由命中了预期供应商渠道和模型部署；
- 参考估算成本能够展示，或明确显示暂无参考价；
- Virtual Key 的租户、项目、应用归因正确。

## 15. 常见问题

### 15.1 模型发现不到

检查供应商是否提供 `/models` 接口、当前 Key 是否有模型权限，以及模型是否需要先在供应商控制台开通。

### 15.2 连接测试 403

检查目标 API 域名是否在出口白名单中，不要填写协议、路径或通配符。

### 15.3 模型可以调用但没有参考价格

不影响调用。等待系统下一次自动同步，或在“参考价格状态”中查看 LiteLLM、models.dev 来源状态。

### 15.4 Virtual Key 调用提示模型不可用

依次检查：

```text
企业服务模型是否发布
→ 路由是否启用
→ 模型部署是否启用
→ 供应商渠道是否健康
→ Virtual Key 是否授权该企业服务模型
```

### 15.5 供应商真实模型升级或下线

新增模型部署或修改路由，不要直接修改业务系统使用的企业服务模型名。完成验证后切换路由，即可保持业务调用地址和模型名不变。
